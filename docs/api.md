# Walletly — API и решения этапа 1

Полный список эндпоинтов со схемами — Swagger: `http://localhost:8000/docs`.
Все маршруты под префиксом `/api`. Данные пространства — под `/api/ledgers/{ledger_id}/...`.

| Раздел | Маршруты |
|---|---|
| Авторизация | `/auth/register`, `login`, `refresh`, `logout`, `me`, `change-password` |
| Пространства | `/ledgers`, `/ledgers/{id}`, `/ledgers/{id}/members` |
| Счета | `/ledgers/{id}/accounts` |
| Категории | `/ledgers/{id}/category-groups`, `/ledgers/{id}/categories` |
| Операции | `/ledgers/{id}/transactions` (фильтры, `limit`/`offset`) |
| Аналитика | `/ledgers/{id}/analytics/summary`, `by-category`, `by-author`, `monthly` |
| Импорт | `POST /ledgers/{id}/import` (`dry_run` — только проверка) |
| Приглашения | `/ledgers/{id}/invitations`, `/invitations/{token}`, `accept`, `decline` |
| Админ | `/admin/stats`, `/admin/users` |

## Принятые решения

Решения приняты при сборке без обсуждения — все с пометкой «разобрать»: можно пересмотреть.

| # | Вопрос | Решение | Почему | Статус |
|---|---|---|---|---|
| 1 | Права в пространстве | Настройка счетов и категорий — owner/admin. Операции создаёт любой участник, меняет только свои; owner/admin — любые | Семья ведёт учёт вместе, но справочники общие | разобрать |
| 2 | Посторонний и чужой ledger | 404, а не 403 | Не раскрывать, что такое пространство существует | разобрать |
| 3 | Перевод между валютами | Запрещён: только счета одной валюты | В операции одна сумма; для курса нужны две суммы и изменение схемы | разобрать |
| 4 | Аналитика при нескольких валютах | Параметр `currency`, суммы не смешиваются | Сумма рублей и долларов бессмысленна. Конвертации по курсу нет | разобрать |
| 5 | Формат денег в JSON | Строка (`"100.50"`) | JavaScript исказил бы сумму, превратив её в float | разобрать |
| 6 | Пагинация | `limit`/`offset` | Просто; на глубоких страницах медленно, тогда перейдём на keyset | разобрать |
| 7 | Приглашения без почты | Ссылку копирует и отправляет сам пригласивший. Принять может только аккаунт с тем email | Почтового сервера пока нет | разобрать |
| 8 | Email при регистрации не подтверждается | Пока так (`docs/auth.md`) | Без подтверждения можно зарегистрировать чужой email; опасно только вместе с украденной ссылкой-приглашением | разобрать |
| 9 | Импорт: ошибка в строке | Весь файл отменяется, список ошибок по строкам, `dry_run` для проверки | После исправления файла не будет дублей | разобрать |
| 10 | Импорт: повторная загрузка | Сравнение с базой как мультимножества: совпадают дата, тип, сумма, счета, категория, описание | Идемпотентность без отдельной колонки, две одинаковые покупки не теряются. Ошибочно пропустит настоящий дубль, если операция уже внесена руками | разобрать |
| 11 | Импорт: колонки | Фиксированный шаблон: Дата, Тип, Сумма, Счёт, Счёт зачисления, Категория, Описание | Формат банковских выписок разный — их парсинг в этапе 5 | разобрать |
| 12 | Две вкладки и ротация refresh | Запросы сериализует фронт (Web Locks), сервер без изменений | Иначе вторая вкладка выглядит как кража и завершает все сессии. Потерянный ответ на refresh всё ещё выкинет на вход | разобрать |
| 13 | Создание операции при двойном клике | Защита только в интерфейсе (кнопка блокируется) | На сервере нужен idempotency key — тема отдельного занятия | разобрать |
| 14 | Лимиты категорий | Колонка `categories.monthly_limit`, один лимит на месяц, без истории | Нужны экранам из дизайна. Отдельная таблица понадобится для лимитов по месяцам | разобрать |
| 15 | Сверка остатков | Пользователь вводит сумму из банка, расхождение прибавляется к `initial_balance` счёта | История операций не меняется. Альтернатива — отдельная корректирующая операция: виден след правки, но она попадает в доходы/расходы | разобрать |
| 16 | Прогноз на экранах | Линейно: расходы за прошедшие дни растягиваются на весь месяц, вместо «уверенности» показан прогресс месяца | До этапа ML нет модели, поэтому процент уверенности был бы выдумкой | разобрать |
| 17 | Сравнение с прошлым месяцем | Текущий неполный месяц сравнивается с теми же днями прошлого, завершённый — с полным | Иначе в начале месяца всё выглядит как падение | разобрать |
| 18 | Walletly AI до этапа ML | Экран считает по правилам (`services/insights.py`): прогноз, необычные траты, перерасход, лимиты. Автокатегоризация из макета заменена карточкой лимитов | Модели пока нет. Рисовать её результаты значило бы обманывать пользователя; на экране есть сноска, что это статистика | разобрать |
| 19 | Кольцо на Walletly AI | Вместо «точности прогноза» показан процент прошедшего месяца | Точность нечем измерить, а прогресс месяца честно говорит, сколько данных уже есть | разобрать |
| 20 | Онбординг и настройки уведомлений | Флаг `users.onboarding_completed` и JSONB `users.notifications` | Флаг нужен на сервере, чтобы онбординг не повторялся на другом устройстве. JSONB — пока типов уведомлений мало и по ним нет запросов; когда появится доставка, возможно, понадобится таблица | разобрать |
| 21 | Журнал действий администратора | Таблица `admin_audit_log` со снимками email, запись в той же транзакции, что и действие | Снимок сохраняет историю после удаления пользователя, общая транзакция не даёт действию пройти без записи | разобрать |
| 22 | Экспорт отчёта | Только Excel, колонки совпадают с импортом, текст записывается как строка | Файл можно загрузить обратно. Запись строкой защищает от выполнения формул из описаний операций. PDF отмечен «Появится позже» | разобрать |
| 23 | Выпадающие списки | `@base-ui/react` вместо `<select>`, тема дублируется на `<html>` | Системный список нельзя оформить по макету. Портал рисуется в `body`, поэтому тема с внутреннего контейнера до него не доходит | разобрать |
| 24 | Копилка | Живёт в пространстве, счёт — вклад, накопительный или наличные. Накопленное = сумма пополнений. Перенос в другое пространство меняет счёт, старые переводы остаются. Прогноз: остаток / взнос с округлением вверх, пропуск — нет пополнения за календарный месяц. Напоминают всем участникам с выбранного числа. Проценты по вкладу не учитываются | Ответы на открытые вопросы бэклога — предложены Claude, ждут решения | разобрать |
| 25 | Лимиты входа | 10 неверных попыток с адреса на email и 100 с адреса за 15 минут, счётчик в Redis. Если Redis недоступен, лимит не действует | Блокировка по одному email позволила бы закрыть вход чужому аккаунту. Распределённый подбор с разных адресов так не остановить, остаётся медленный Argon2 | разобрать |
| 26 | Подтверждение email | Не запрещает пользоваться приложением, только показывает напоминание в профиле | Письмо может задержаться, а данные пользователю нужны сразу | разобрать |
| 27 | Уведомления | Таблица `notifications`, проверка раз в час в `worker`, повтор отсекает уникальный ключ события. Семейные операции сводятся в одно уведомление в день | Письмо на каждую операцию превратилось бы в спам | разобрать |
| 28 | PWA | Свой `sw.js` без плагина: кэшируются только статика и оболочка, API никогда | На общем устройстве в кэше не должны оставаться финансовые данные | разобрать |
| 29 | ЮKassa | Статус платежа запрашивается у API ЮKassa, тело уведомления не считается доказательством. Автосписаний и чека 54-ФЗ нет | Подделка уведомления не даёт Premium. Автосписания требуют согласования с ЮKassa, чек нужно настроить под форму договора. Запросы к настоящему API ещё не проверены: нужны ключи тестового магазина | разобрать |
| 30 | Цена и тарифы | Premium 299 ₽ за 30 дней (`PREMIUM_PRICE_RUB`). Free: одна копилка на пространство, подсказки на правилах | Цена-заглушка, решение за владельцем продукта | разобрать |
| 31 | Модели категорий | Отдельная модель на пространство: категории у всех свои. Хранятся в `ml_models`, обучаются ночью только для Premium, нужно от 20 операций с описанием | Общая модель потребовала бы сопоставлять чужие названия категорий. Минус: новым пользователям подсказки недоступны, пока нет данных. Точность завышена повторами описаний: это узнавание знакомого | разобрать |
| 32 | A/B-тест категорий | A — scikit-learn, B — PyTorch. Вариант закреплён за пользователем по crc32, сравнивается доля принятых подсказок, итог — от 100 решений на вариант и p < 0,05 | Без реальных пользователей итога не будет. PyTorch увеличивает образ примерно на гигабайт; ради этой задачи без сравнения он не нужен | разобрать |
| 33 | Прогноз и аномалии | Ridge по доле прошедшего месяца с проверкой на отложенных месяцах, IsolationForest для трат. Без трёх полных месяцев или 40 операций остаются правила. Рекомендации по-прежнему считаются правилами | Точность показывается только измеренная, а неполный первый месяц отбрасывается | разобрать |
| 34 | Telegram-бот | Отдельный процесс на long polling, привязка одноразовой ссылкой на 10 минут, расходы пишутся в личное пространство на первый счёт. Если категория не определена, бот не записывает операцию | Боту не нужен публичный адрес. Лучше спросить, чем исказить аналитику | разобрать |
| 35 | PDF-выписки | Общий разбор строк: дата в начале, сумма в конце, плюс означает поступление. Нераспознанное идёт в «Прочие расходы/доходы». Переводы между своими счетами выглядят как расход и доход | Настоящие выписки Сбера, ВТБ и Хлынова ещё не проверены: нужны образцы. Сканы не читаются | разобрать |
| 36 | HTTPS на сервере | Caddy перед `web` | Сам получает и продлевает сертификат. Nginx + certbot потребовал бы больше настройки и отдельный таймер продления | разобрать |
| 37 | Открытые порты | База, API и `web` привязаны к `127.0.0.1`, снаружи только 80 и 443 у Caddy | Docker обходит ufw, поэтому одного файрвола недостаточно | разобрать |
| 38 | Бэкапы | `pg_dump` раз в сутки в `backups/`, хранение 14 дней, проверка через `deploy/restore.sh` на отдельной базе | Дёшево и проверяемо. Копии лежат на том же сервере, внешнее хранилище ещё нужно подключить | разобрать |
| 39 | CI/CD | GitHub Actions, выкат запускается только вручную | В плане был GitLab CI, но репозиторий на GitHub | разобрать |
| 40 | Мониторинг | Prometheus и Grafana в необязательном профиле, `/metrics` наружу не отдаётся | Не тратить память на маленьком сервере | разобрать |

## Что осознанно не сделано

- Вход через Google, двухэтапная проверка, список устройств в сессиях (сейчас только количество).
- Экспорт в PDF.
